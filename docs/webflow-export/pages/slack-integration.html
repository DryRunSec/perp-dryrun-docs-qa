How It Works

DryRun Security sends notifications to Slack through standard incoming webhooks. You create a Slack incoming webhook URL in your Slack workspace, register it in DryRun Security under Settings > Webhooks, and assign it to configurations to control which repositories and severity levels trigger notifications.

Each notification includes the repository name, pull request title, severity level, and a direct link to the pull request. Links open directly to the relevant PR.

Adding a Slack Webhook

In the DryRun Security app, navigate to Settings > Webhooks and click Add Webhook. Select Slack as the type, enter the Slack webhook URL, give the webhook a name, and save. The name is used to reference this webhook when assigning it to configurations.

A Generic webhook option is also available for sending notifications to any HTTP endpoint. The setup is identical; messages are sent as JSON-formatted POST requests.

Scoping Notifications

Once a webhook is saved, assign it in a configuration to control which repositories trigger notifications.

A webhook assigned in the Default Configuration covers all repositories in your organization. A webhook assigned to a targeted configuration covers only the repositories included in that configuration.

In the configuration's Notifications tab, select the webhook by name and set the minimum severity level that triggers a notification. Only findings at or above that severity generate a Slack message.

Webhook Payload

Generic webhook notifications are JSON-formatted POST requests. The payload includes the repository name, PR title, finding severity, and a direct URL to the finding in the DryRun Security Risk Register.
